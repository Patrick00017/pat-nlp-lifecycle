```
│  │ (FSM 引擎)   │  │              │  │  (文件上传/构建/查询)     │ │
│  └─────────────┘  └──────────────┘  └─────────────────────────┘ │
└──────────┬───────────────────────────────────┬───────────────────┘
           │                                   │
           ▼                                   ▼
┌───────────────────┐             ┌───────────────────────────────┐
│   SQL Server      │             │      OpenCode AI 引擎          │
│  (产线运行数据库)   │             │         (:4097)                │
│                   │             │                               │
│  · shly-rundata   │             │  · 时间线分析智能体 (Agent)     │
│  · shly-basedb    │             │  · 文档问答智能体 (RAG Agent)   │
│                   │             │  · AI 模型 (本地/云端)          │
└───────────────────┘             └───────────────────────────────┘
```

### 1.2 各层职责

| 层 | 职责 |
|----|------|
| **前端** | 提供 4 个功能页面（事件诊断、订单匹配、文档助手、知识库管理），实时渲染诊断结果与 AI 对话 |
| **后端 (FastAPI)** | 接收前端请求，调度 FSM 诊断引擎、订单匹配引擎处理产线日志；管理知识库文档上传与向量索引构建 |
| **SQL Server** | 存储产线实时运行数据（HisRunningData）、基础参数档案（GlueGu/SPC_GlueWeight 等）、订单信息 |
| **OpenCode AI 引擎** | 提供 AI Agent 调度能力，结合诊断数据给出自然语言分析结论；管理 RAG 检索与 LLM 对话 |

### 1.3 服务端口一览

| 服务 | 端口 | 说明 |
|------|------|------|
| 后端 API | 8082 | FastAPI 服务，前端直连 |
| OpenCode AI | 4097 | AI 引擎，由后端代理 |
| SQL Server | 56566 | 产线数据库（远程） |

## 2. 功能模块

### 3.1 事件诊断

**功能说明**：自动分析指定时间段内的糊间隙事件，逐项校验每个胶水赋值计算是否正确，并以时间线形式展示诊断结果。

**校验项目（5 大参数）**：

| 校验项 | 说明 | 异常示例 |
|--------|------|----------|
| 材质匹配 | 赋值使用的材质码是否与当前实际材质一致 | 赋值用 "HD"，实际材质为 "07" |
| 克重匹配 | 计算的当前克重是否与数据库中档案克重一致 | 计算值 480g，档案 500g |
| QDM 系数 | QDM（胶水扩散系数）是否与数据库配置一致 | 系数 0.85，档案 0.90 |
| 基础资料 | min_glue/max_glue 等参数是否与数据库一致 | min_glue 10，档案 12 |
| 车速系数 | 车速补偿系数是否与数据库配置一致 | 系数 1.05，档案 1.00 |

**异常等级**：

| 等级 | 颜色 | 含义 |
|------|------|------|
| 🔴 错误 | 红色 | 直接影响配方的参数错误（材质、QDM、车速系数） |
| 🟠 警告 | 橙色 | 需关注但不影响配方的偏差（克重、基础资料） |
| ✅ 通过 | 绿色 | 校验正常 |

**操作方式**：

1. 选择"事件诊断"标签页
2. 左侧显示时间线事件列表，每个事件标注校验结果（颜色标签）
3. 点击任一事件，右侧展开详细校验报告（每个参数的具体比对值）
4. 点击报告右上角的 ✨ 按钮，AI 助手自动分析并给出诊断结论

### 3.2 订单匹配

**功能说明**：将每次换材事件与当前执行的订单要求进行比对，判断换材是否与订单材质一致。支持从 16 个槽位维度进行全量核对，自动追溯不匹配材质的来源订单。

**泳道图说明**：

系统以竖向表格形式展示订单切换的时间线，横轴为 16 个槽位列：

| 列 | 说明 |
|----|------|
| 时间 | 事件发生的时间点 |
| 订单 | 当前执行的订单号 |
| ls0 ~ df | 6 个接纸机槽位的材质匹配状态 |
| GU1 ~ GU3 / SF1 ~ SF2 | 胶水槽位，显示当前使用的材质码及分析结果 |

**颜色含义**：

| 颜色 | 材料列含义 | 胶水列含义 |
|------|-----------|-----------|
| 🟢 绿色 | 材质与订单一致 | 校验正常 |
| 🔴 红色 | 材质与订单不一致 | 未知材质错误（找不到匹配源） |
| 🟠 橙色 | — | 换材滞后（仍在用上一订单的材质） |
| 🟡 黄色 | — | 换材提前（已为下一订单备料） |
| 🟣 紫色 | — | 实际材质触发（产线 ERP 直送，以实际为准） |
| ⬜ 灰色 | 该槽位无材质数据 | — |

**溯源功能**：

当材质与订单不匹配时，系统自动在全部历史订单中进行双向搜索，找到最匹配的订单号，标注在单元格的悬停提示中，帮助快速定位"这笔材质本应属于哪个订单"。

**操作方式**：

1. 选择"订单匹配"标签页
2. 页面展示完整的订单匹配泳道图
3. 鼠标悬停在任意单元格上，查看详细对比和溯源信息
4. 点击胶水列单元格，弹出详情面板：
   - 左侧：该胶水事件的完整校验报告（5 大参数明细）
   - 右侧：AI 智能分析面板（点击 ✨ 按钮获取）
5. 点击材料列单元格，弹出换材详情（含纸卷剩余量变化图）

### 3.3 文档助手

**功能说明**：基于已构建的知识库，提供智能问答服务。用户可以像询问一位经验丰富的老师傅一样，用自然语言提问，系统自动从文档中检索相关内容并给出准确回答。

**典型问题示例**：

- "如何进行订单修改？"
- "IPS 系统的参数保存在哪里？"
- "糊机换材的操作步骤是什么？"
- "SF1 的 QDM 系数如何配置？"

**操作方式**：

1. 选择"文档助手"标签页
2. 在输入框中输入问题（中文）
3. 系统自动检索知识库文档，生成回答
4. 如果首次回答不够精准，可追问或换一种方式提问

**注意事项**：

- 回答仅基于已上传的文档内容，不会编造信息
- 如果文档中没有答案，系统会明确告知，请勿重复提问
- 知识库内容由"知识库管理"模块进行维护

### 实现方式

**RAG（检索增强生成）架构**：系统将文档预先转化为向量索引，用户提问时先从知识库检索最相关内容，再将片段与问题提交 AI 生成回答，确保有据可查。

| 环节 | 技术选型 |
|------|----------|
| 文档解析 | PyMuPDF（PDF）、python-docx（Word）、原生读取（TXT/MD） |
| 文本分块 | LangChain RecursiveCharacterTextSplitter（块大小 500 字，重叠 100 字） |
| 向量化模型 | BAAI/bge-small-zh-v1.5（本地部署，中文语义优化） |
| 向量存储 | Chroma（本地持久化，无需外部服务） |
| 前端通信 | SSE（Server-Sent Events）流式传输 |
| AI 编排 | OpenCode Agent 框架，挂载 rag_search 检索工具 |

### 流程

```
        【构建阶段】                      【查询阶段】

        用户上传文档                       用户提问
            │                                │
            ▼                                ▼
        文档解析                         问题向量化
      (PDF/DOCX/TXT/MD)               (同一嵌入模型)
            │                                │
            ▼                                ▼
        文本分块                         相似度检索
    (500字/块, 重叠100字)             (Chroma 向量库)
            │                                │
            ▼                                ▼
        向量化                           LLM 生成回答
     (768维中文向量)                 (片段+问题→AI模型)
            │                                │
            ▼                                ▼
       存入 Chroma                       SSE 流式返回
      (本地持久化)                      (前端逐字渲染)
            │                                │
         ✓ 构建完成                       ✅ 回答呈现
```

### 文档编写建议

为了让 LLM 更准确理解文档内容并生成高质量回答，上传文档时请注意以下要点：

**推荐做法**：

| 建议 | 说明 |
|------|------|
| 使用清晰的层级标题 | 大标题、小标题分明的文档更易被分块和检索 |
| 采用步骤式描述 | 操作步骤用"第一步""第二步"或编号列表编写，LLM 可直接引用 |
| 表格优于纯文字 | 参数对照、配置说明等用表格呈现，结构化数据检索命中率更高 |
| 定义专业术语 | 在文档开头或附录统一说明缩写和术语，避免 LLM 误解 |
| 适当分段 | 每段 200~500 字为佳，与分块大小匹配，避免语义被切断 |
| 关键信息用文字 | 操作流程、参数定义等避免仅靠截图，用文字描述确保可检索 |

**应避免**：

| 问题 | 影响 |
|------|------|
| 扫描件 PDF（无文字层） | 系统无法识别图片中的文字，需先 OCR 处理 |
| 超大单文件（>50MB） | 解析和向量化耗时长，建议按章节拆分为多个文件 |
| 密集表格无标题 | 分块后表格被截断，LLM 无法理解完整上下文 |
| 英文为主中文混杂 | 当前嵌入模型针对中文优化，纯英文文档检索效果较差 |
| 缺少版本号 | 多次上传覆盖后无法追溯文档版本，建议文件名包含日期或版本号 |

**格式示例**：

```
文档标题：IPS 系统操作手册 v2.1

## 1. 订单管理
### 1.1 创建订单
  第一步：进入"订单管理"页面
  第二步：点击"新建订单"按钮
  第三步：填写以下信息：
    | 字段 | 说明 | 示例 |
    |------|------|------|
    | 订单号 | 系统自动生成 | 9102 |
    | 材质码 | 全材质编码 | HD.07.07.07.B9 |
```

### 3.4 知识库管理

**功能说明**：管理系统知识库的文档。支持上传操作手册、工艺规范、设备说明等文档，系统自动解析并构建可被搜索的知识索引。

**支持的文档格式**：

| 格式 | 说明 |
|------|------|
| PDF | 产线操作手册、设备说明书（推荐） |
| TXT | 纯文本文档 |
| MD | Markdown 格式的技术文档 |
| DOCX | Word 文档 |

**构建策略**：替换式构建。每次点击"构建知识库"时，系统会清空旧索引，基于当前上传的全部文件重新构建。

**操作流程**：

```
上传文档 → 构建知识库 → 文档助手即可使用
```

具体步骤：

1. 选择"知识库管理"标签页
2. 将文档拖拽到上传区域，或点击"选择文件"按钮
3. 确认文件列表无误后，点击"🔨 构建知识库"
4. 等待构建完成（时间取决于文档总量）
5. 切换到"文档助手"标签页进行测试

**文件管理**：

- 上传区域支持拖拽和点击上传
- 文件列表显示文件名和大小
- 点击文件右侧的 ✕ 按钮可删除单个文件

**构建说明**：

- 系统会自动对文档进行分块（每块约 500 字），构建向量索引
- 构建完成后会显示生成的文档块数量
- 如果构建失败，检查文件格式是否正确、文件是否损坏

## 3. 部署说明

### 4.1 前置条件

- Python 3.10+（推荐使用 conda 环境 `pat-nlp-lifecycle`）
- Node.js 16+
- 能够访问 SQL Server 数据库（192.168.110.195:56566）
- 本地 AI 嵌入模型已下载（`model/bge-small-zh-v1.5/`）

### 4.2 启动步骤

**第一步：启动 OpenCode AI 引擎**

```bash
cd bts_analysis_sandbox
opencode serve --port 4097 --hostname 127.0.0.1
```

**第二步：启动后端 API 服务**

```bash
cd bts_analysis_sandbox
uvicorn api:app --reload --port 8082
```

**第三步：构建前端（生产环境）**

```bash
cd agent_frontend
npm run build
```

构建产物输出至 `agent_frontend/dist/`，部署到任一 Web 服务器（如 Nginx）即可。

**第四步：访问系统**

在浏览器中打开前端页面地址。若使用开发模式：

```bash
cd agent_frontend
npm run dev
```

默认访问 `http://localhost:5173`。

### 4.3 首次部署注意事项

1. **知识库准备**：首次部署时需在"知识库管理"中上传操作手册等文档，并点击"构建知识库"，此后"文档助手"才可正常使用
2. **数据库连接**：确保 `config.yaml` 中的数据库地址、账号密码正确，否则诊断功能无法获取基础档案
3. **嵌入模型**：确保 `model/bge-small-zh-v1.5/` 目录存在且文件完整（该模型用于文档向量化，约 400MB）

## 4. 配置说明

系统配置文件位于 `bts_analysis_sandbox/config.yaml`：

| 配置项 | 字段 | 说明 |
|--------|------|------|
| 运行数据库 | `database.server` | SQL Server 地址 |
| 运行数据库 | `database.database` | 数据库名（默认 `shly-rundata`） |
| 基础数据库 | `basedatabase.server` | 基础档案库地址 |
| 基础数据库 | `basedatabase.database` | 数据库名（默认 `shly-basedb`） |
| OpenCode 地址 | `opencode.host` | AI 引擎地址（默认 `127.0.0.1`） |
| OpenCode 端口 | `opencode.port` | AI 引擎端口（默认 `4097`） |
| OpenCode 密码 | `opencode.password` | AI 引擎访问密码 |
| 项目目录 | `opencode.project_directory` | AI 引擎的工程根目录 |

> **实施注意事项**：如客户环境数据库地址或端口不同，需修改上述对应字段。前端无需单独配置，所有后端地址由 API 统一管理。

## 5. 常见问题

### Q1：知识库如何更新？

在"知识库管理"中上传新文档（或删除旧文档），点击"构建知识库"即可。系统会以最新上传的文件重新构建整个知识库。

### Q2：诊断结果为空怎么办？

诊断结果需要先触发产线日志分析流程。确认后端已正确连接到 SQL Server（可通过 `/api/health` 检查），且分析脚本正常运行。

### Q3：文档助手回答不准确怎么办？

- 确认知识库已构建完成（知识库管理页显示文件列表和构建状态）
- 检查上传的文档是否包含相关内容
- 尝试换一种提问方式或更换关键词
- 如果持续不准确，考虑补充更完整的操作文档

### Q4：构建知识库失败？

常见原因：
- 上传的文件损坏或格式不支持（仅支持 PDF/TXT/MD/DOCX）
- 服务器磁盘空间不足
- 嵌入模型文件缺失（检查 `model/bge-small-zh-v1.5/` 目录）

### Q5：系统可以同时给多个客户部署吗？

可以。每个客户部署独立的服务实例，通过 `config.yaml` 配置各自的数据库连接。如需定制前端界面样式，可通过 CSS 变量统一修改配色。

### Q6：AI 分析结论的可信度如何？

AI 分析基于真实的产线数据库和事件数据，分析逻辑与人工排查流程一致（先校验参数 → 再比对订单 → 最后追溯来源）。AI 的优势在于速度快、不遗漏，建议作为人工判断的辅助手段。
